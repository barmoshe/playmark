How it works

  1. 01

    Play

    Playmark keeps the last five seconds while you play.

  2. 02

    Mark

    CtrlShiftM freezes the frame. Click to pin, drag to box, 1 to 5 for a category, then a note.

  3. 03

    Your agent fixes

    Claude Code mentions new marks on your next prompt; in Codex, ask it to triage. It finds the code under your pin and proposes a fix. You say which.

  4. 04

    Retest

    The game says "Fixed #3" and leaves a marker where you made the mark.

In a real game

Redesigning an enemy in Wandcraft

Wandcraft is a pixel-art roguelite. Its Thornback, an enemy that charges at you, looked like a loaf of bread. One mark, mid-fight:

Redesign the Thornback: make it look like a charging ram, with curled horns, thorns along its back and a glowing eye.
  1. The box found the node. enemy.gd, kind ram, with the run's state: room, wave, hp, the wand.
  2. Claude found the art. 16 rows of pixel data in bestiary.gd, drawn with the game's palette rules.
  3. The redraw. A hunched back, bramble spikes, a curled horn, a glowing eye.
  4. Back in the fight. "Fixed #1", and the marker stays where the mark was made.

What your agent gets

Every mark is a folder in .playmark/inbox, git-ignored by default. This is the real one from the video.

  • annotated.pngthe frame, pins numbered
  • clip_sheet.pngthe last seconds, oldest first
  • log.txtwarnings and errors
  • mark.jsonnote, scene, the nodes and scripts under each pin, your game's state

Inside

What it does

  • Rewind

    Missed the moment? Step back up to five seconds and mark that frame.

  • The code under your pin

    Colliders, nodes, scripts and UI controls, per pin and box.

  • Ghosts

    Past marks stay in the world where you made them. Orange is open, blue is fixed.

  • Errors mark themselves

    A script error becomes a bug mark, with the clip and the log.

  • Warp back

    Open the game at a mark. The agent can grab a frame to check its fix.

  • Your game's state

    One line adds the player, the level or the loadout to every mark.

  • Sharp at any resolution

    The overlay is its own window, so pixel-art games read fine.

  • Share without AI

    One command turns the marks into a page anyone can open.

  • Dev builds only

    Nothing runs in a release export unless you turn it on.

Install

Install in Claude Code or Codex

Claude Code

  1. /plugin marketplace add barmoshe/playmark
  2. /plugin install playmark@playmark
  3. /playmark:installin your game's repo

Codex

  1. codex plugin marketplace add barmoshe/playmark
  2. codex plugin add playmark@playmark
  3. Install Playmark in this gamein your game's repo

Godot 4.5+ or Unity 6+Claude Code or CodexNode 18+Desktop, tested on macOS

No agent? Mark, export, share

Copy addons/playmark into a Godot project and enable it in Project Settings, Plugins (Unity: add the package by git URL). Play and mark as usual, then turn the marks into one page you can open or send to anyone:

  1. git clone https://github.com/barmoshe/playmark
  2. node playmark/scripts/inbox.mjs exportin your game's folder

From nothing

Start a new game with it

A blank Godot project with Playmark already in it: one playable scene, an AGENTS.md that teaches the loop, and a first commit. Say what game to build, play each step, mark what's off.

  1. /playmark:new star-dodger --name "Star Dodger"Claude Code
  2. Start a new Playmark game in star-dodgerCodex
  1. Build a step. One mechanic, one enemy, one screen.
  2. Play it. CtrlShiftM on whatever is off.
  3. Triage. /playmark:triage, or ask Codex. It fixes what you pick.
  4. Commit. Then the next step.

Why

I made Playmark while building Wandcraft, a roguelite where you program your wand. Playtesting my own game, I kept noticing small things I didn't want to stop and write up. Now I press a key, point, and keep playing.
